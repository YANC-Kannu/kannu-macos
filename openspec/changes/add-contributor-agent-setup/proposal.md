# Change: Give every contributor, and every contributor's agent, the same working setup

## Why
A read-only audit of `development` (75e62b24, 2026-11-16) found OpenSpec structurally valid
(`validate --all --strict`: 8 of 8) but not enforced, and found that a fresh clone gets the rule layer without the
working layer:
- the rules (`AGENTS.md`, `CLAUDE.md`, the specs, the hook) are committed, but the tools that make them practical
  (merge resolvers, snapshot-board and install scripts, gate skills) live only on maintainers' machines;
- the specs cover the Brain redesign and the release, but not the agent monitor, which is the product's core and its
  most fragile part, nor most other shipped features;
- only Claude Code gets OpenSpec commands, and skills sit in three tool-specific folders that each tool alone sees;
- nothing asks a behaviour-changing PR for a spec delta, and the hook's CHANGELOG gate does not cover the agent and
  OpenSpec folders.

The quick wins ship with 2.0, in the same PR as this proposal. Everything else waits until after 2.0 and is
recorded here so it is not lost.

## What Changes
- **Shipped with 2.0 (this PR), recorded in `tasks.md` section 1:**
  - `.claude/settings.json` no longer pre-approves `git push`; it allows only read-only git, the KannuTests run, the
    pinned OpenSpec `list` and `validate`, and the pre-commit hook;
  - `CLAUDE.md` makes the `caveman` style skill optional;
  - `openspec/project.md`: the hold rule names a maintainer, not a person; the context says the specs describe
    `development`; the feed line and the new branch rulesets are current;
  - an OpenSpec CLI note in `AGENTS.md`, and the Claude OpenSpec commands use the pinned CLI;
  - a CI job on ubuntu that runs the pinned `openspec validate --all --strict` and the pre-commit hook;
  - `.gitignore` covers `marketing/`, `*.local.md`, `.claude/worktrees/` and `.claude/settings.local.json`;
  - a Setup checklist at the top of `CONTRIBUTING.md`.
- **After 2.0 (this proposal's backlog):**
  - **As-built specs** for `agent-status` (including #55's non-blocking Claude hooks and the status line),
    `agent-security`, `usage-limits`, `timer`, `launch-gate`, `updates` and the notch surfaces (media, HUD, lock
    screen, shelf), each citing the rule tests that already pin it;
  - **`scripts/doctor.sh`**, a read-only setup check that `install-git-hooks.sh` runs at its end;
  - **committed merge resolvers** for `CHANGELOG.md` (entries ordered by date) and for `Kannu/Localizable.xcstrings`
    (key by key, with a lost-key check);
  - **`scripts/snapshot-boards.sh`**, and `--identity` and `--install` options on `scripts/build-launch-app.sh`;
  - **shared skills** `kannu-gates`, `kannu-boards` and `kannu-build-launch`, canonical under `.agents/skills/`, with
    symlinks from `.claude/skills/` and `.cursor/skills/`;
  - **OpenSpec commands for Cursor and GitHub Copilot**, generated by 0.23.0 in a scratch checkout and committed
    without its `CLAUDE.md` edit;
  - **a PR template and `CODEOWNERS`**;
  - **the hook's source paths** extended to `.claude/`, `.agents/`, `.cursor/` and `openspec/`;
  - **a cloud SessionStart setup** that installs the hooks and checks for Node;
  - **release-2-0's deltas** split by capability and archived as each one's code lands.
- New capability spec: `contributor-setup`.

## Impact
- Affected specs: `contributor-setup` (new).
- Affected code: none in the app. Scripts, CI, instruction files, agent folders and `openspec/` only.
- Not a 2.0 gate. Nothing in the backlog blocks `v2.0.0-beta.2` or `v2.0.0`.
